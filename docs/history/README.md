## Evidence boundaries

The edit-chain record separates Inspector checks from reported Engine consumer
checks. A local build does not establish native history, visual acceptance,
package publication or automatic consumer adoption. The
[current guide](../edit-chains.md#view-parity-and-release-boundary) explains

[Development checks](../development.md#checks) describe procedures. Their
presence does not record a new run. No product tests were reopened to organize
these documents, and no new work or product closure is inferred from a move.

## Future closure

New closures preserve the accepted roadmap block and its outcome in one
Markdown record here, with evidence links, important nested decisions and the
Git planning baseline. Remove completed TODO/task entries instead of copying
both planners into another archive. Use the
[closure template](../templates/CLOSURE-RECORD.md).

Legacy work may have no standalone roadmap block; name that limitation and
reference the original accepted scope rather than inventing one. Existing
archive records stay where they are.
